# Todo Workspace - Next.js Frontend

Next.js App Router frontend for the Todo Workspace application. It provides authentication, Todo workflows, notifications, administrator controls, Scrum management, team analytics, and user history.

## Technology

- Next.js 16
- React 19
- JavaScript
- CSS Modules
- Jest and Testing Library
- ESLint

The frontend uses a Backend-for-Frontend proxy. JWT tokens remain in `httpOnly` cookies and are never returned to browser JavaScript.

## Local setup

```bash
cd todo-workspace-frontend
npm install
npm run dev
```

Frontend URL:

```text
http://localhost:3000
```

Create `.env.local`:

```dotenv
BACKEND_API_URL=http://127.0.0.1:8000/api
```

The Django API must also be running:

```bash
cd todo-api
./venv/bin/python manage.py runserver 127.0.0.1:8000
```

## Environment variables

| Variable | Required | Description |
|---|---:|---|
| `BACKEND_API_URL` | Yes | Django API base, including `/api`; for local use `http://127.0.0.1:8000/api` |

Do not expose Django JWT secrets or add tokens to `NEXT_PUBLIC_*` variables.

## Admin features

### Dashboard

The dashboard displays:

- Workspace totals for the last 14 days
- Completion and incomplete Todo counts
- Bottleneck cards
- Team summary bars
- User activity
- Recent activity
- 90-day completion heatmap

### Scrum management

Scrums are managed from each team detail page. The lifecycle is:

1. Create -> status is `created`
2. Start -> status is `running`
3. End -> status is `ended`

Scrum names are generated by the backend as `scrum-1`, `scrum-2`, and so on. An ended Scrum shows a disabled Finished button.

### Team analytics

Each team detail page includes:

- Task creation trend for the last six months
- Weekly completion velocity for the last six months
- Optional Scrum-specific filtering

### User history

The user detail page contains:

- Assigned-to-user and assigned-by-user tabs
- Scrum filtering
- Category filtering
- From/to date filtering
- Debounced URL updates
- Todo cards
- Completed, priority, assignment, response-time, on-time, and overdue statistics

The filters do not require a separate Apply button.

### Bottleneck details

Bottleneck cards open dedicated detail pages for:

- Pending assignments
- Overdue Todos
- Unassigned Todos
- High-rejection users
- Overloaded users
- Inactive users

Details use the same 14-day reporting period as the dashboard summary.

## Authentication and backend proxy

- Login and logout use Next.js route handlers.
- Access and refresh tokens are stored in `httpOnly` cookies.
- `/api/[...path]` proxies browser requests to Django.
- `src/lib/proxy-allowlist.js` restricts forwarded methods and paths.
- Server Components use `src/lib/backend.js` with the access token cookie.
- Middleware refreshes tokens before access-token expiry.
- Backend permissions remain authoritative.

## Filtering and caching

- URL search parameters represent filters and paging, allowing bookmarkable pages.
- Debounced text and history filters update after a short delay.
- Category and team data use server cache tags.
- Dashboard data uses short revalidation.
- Todo and notification data are not cached beyond normal Next.js request behavior.
